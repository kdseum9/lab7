При изменении проекта необходимо соблюдать следующие конвенции:
1. Command classes
   Каждая новая пользовательская команда должна быть реализована отдельным классом в пакете command.
   Класс новой команды должен наследоваться от AbstractCommand
   Класс команды должен отвечать за выполнение пользовательской команды и вызывать соответствующие менеджеры для выполнения операций, относящихся к их ответственности.
   Нельзя реализовывать новую пользовательскую команду непосредственно в Client или Server; для неё должен быть создан отдельный класс в пакете command.
2. Database access
   Все операции с PostgreSQL, включая SQL-запросы, создание соединений и изменение данных, должны выполняться в DataBaseManager.  
   Если новая функциональность требует обращения к базе данных, необходимо использовать или расширять DataBaseManager.
   Нельзя создавать отдельный механизм подключения к базе данных или выполнения SQL-запросов вне DataBaseManager.
3. Validation
   Проверка моделей должна выполняться с использованием существующих классов-валидаторов в пакете manager.
   Если для соответствующей модели уже существует валидатор, необходимо использовать его, а не дублировать правила проверки
   Новые правила валидации модели должны добавляться в соответствующий класс-валидатор в пакете manager.
4. Error-handling
   Ошибочные ситуации должны обрабатываться с использованием существующих исключений проекта
   Перед созданием нового типа исключения необходимо проверить, существует ли подходящее исключение в проекте.
   Нельзя заменять механизм существующих исключений произвольными сообщениями об ошибках.
5. Client-Server protocol
   Данные команд, передаваемые между клиентом и сервером, должны передаваться с использованием класса Request.
   Новые параметры команд должны передаваться через существующий механизм Request.
   При расширении протокола необходимо сохранять существующий механизм сериализации и обработки Request.
6. Collection access
   Операции с основной коллекцией приложения должны выполняться через CollectionManager.
   Команды не должны напрямую изменять внутреннюю коллекцию, если необходимая операция может быть реализована через CollectionManager.
   Если для новой команды требуется операция над коллекцией, которой еще нет в CollectionManager, её необходимо реализовать в CollectionManager и вызывать из команды.
   Логику работы с коллекцией нельзя дублировать в нескольких командах.
7. Layer separation
   Client и Server должны содержать код, связанный с сетевым взаимодействием: установкой соединения, отправкой и получением данных, а также обработкой сетевых запросов и ответов.
   Логика выполнения пользовательских команд должна находиться в классах команд пакета command.
   При добавлении новой функциональности код должен размещаться в соответствующем архитектурном слое и не должен дублировать или переносить ответственность другого слоя. 

При добавлении или изменении пользовательской команды используй skill implement-command (.agents/skills/implement-command/SKILL.md).
